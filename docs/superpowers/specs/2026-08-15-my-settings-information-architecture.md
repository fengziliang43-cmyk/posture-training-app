# “我的”与分层设置设计规范

## 目标

把开发配置从普通用户路径中移除，将底栏最后一项从“设置”改为“我的”。“我的”负责呈现用户真正关心的训练档案和个人入口；低频配置进入二级“设置”，再按功能进入独立详情页。

## 已确认的信息架构

### 登录与注册

- 网站继续使用当前域名请求 API。
- Android、iOS 原生客户端固定连接 `https://body.liang111.top`。
- 登录页和注册页不显示服务器地址、连接测试或服务器切换入口。
- 已安装客户端遗留的自定义服务器地址不再覆盖正式地址。

### 主导航

- 底栏固定为“今日 / 记录 / 体态 / 我的”。
- “我的”首页不重复展示右上角已有的账号卡片，也不展示服务器、连接或 AI 状态三宫格。
- “我的”首页只保留：训练档案摘要、训练记录/体态记录快捷入口和“设置”入口。

### 设置首页

设置首页只展示可点击入口，不直接展开完整表单：

1. `DeepSeek AI`：状态、API Key、模型和连接测试。
2. `训练提醒`：提醒开关。
3. `账号与隐私`：个人数据说明、导出、退出登录和账号注销。
4. `规则与说明`：本地训练规则、DeepSeek 边界、照片隐私与风险提示。

训练服务器不作为设置项出现，普通用户不可修改正式服务器。

### DeepSeek

- DeepSeek 入口始终可见，不能因为服务端能力关闭而消失。
- 服务端允许个人 Key 时，详情页直接显示启用开关、Key、模型、保存、测试和清除操作。
- 服务端未启用个人 Key 时，详情页明确说明安全原因，并展示未来开放后的配置步骤；不得提供无法成功的伪表单。
- DeepSeek 只解释本地规则生成的计划，不改变训练决策，不接收体态照片，不做医疗诊断。

## 视觉与交互

- “我的”首屏控制在少量卡片和列表入口内，不使用大段账号/隐私宣言或三宫格状态卡。
- 二级页使用清楚的返回按钮、标题、状态标签和纵向内容；每个入口整行可点击并带箭头。
- 390×844 及常见手机视口不得横向溢出，底栏不得遮挡最后一个操作。

## 验收

- 原生登录/注册页 DOM 中不存在服务器地址和测试连接按钮。
- 原生 API 地址始终解析为正式 HTTPS 地址，忽略旧本地覆盖值。
- 底栏显示“我的”，点击后可进入设置首页。
- DeepSeek、提醒、账号与隐私、规则说明均先显示入口，点击后才显示详情。
- DeepSeek 能力关闭时入口仍存在，并给出真实状态而非隐藏功能。
