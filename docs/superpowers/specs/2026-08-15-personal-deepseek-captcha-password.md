# 个人 DeepSeek、验证码与密码规则修正规范

## 目标

按良 2026-08-15 的要求开放每个账号自己的 DeepSeek API Key，把注册和修改密码的最低长度统一为 6 位，并在公开环境的登录、注册流程加入一次性图形验证码，降低自动化撞库和批量注册风险。

## 个人 DeepSeek API Key

- “我的 → 设置 → DeepSeek AI”始终保留入口；能力开放时显示 Key、模型、保存、测试、开关和清除操作。
- Key 按账号隔离，写入服务端前使用由生产 `COOKIE_SECRET` 派生的独立 AES-256-GCM 密钥加密；数据库只保存带版本的密文。
- Key 只允许写入、替换、连接测试和清除；任何设置接口、错误信息、日志、备份和管理员统计都不得回显 Key 或密文。
- DeepSeek 仍只解释确定性规则已经生成的计划与复盘，不参与选动作、调训练量、医疗诊断或体态照片处理。
- `DEEPSEEK_USER_KEYS_ENABLED` 保留为紧急关闭开关；正式开放时设为 `true`。

## 密码规则

- 注册密码和修改后的新密码统一为 6–128 位；5 位及以下由前后端共同拒绝。
- 界面明确写“至少 6 位，建议使用 10 位以上且不要与其他网站重复”。
- 密码继续使用 bcrypt 哈希，不保存明文；修改成功后撤销该账号全部会话。
- 6 位只是最低兼容线，不代表强密码；登录限流和验证码不能被移除。

## 登录与注册验证码

- 公开环境默认强制开启；登录和注册每次提交都必须携带一份未过期、未使用的四位数字图形验证码。
- 服务端生成随机答案和随机挑战 ID，只返回不含文本答案的七段式 SVG 图片；挑战 5 分钟过期、校验一次即作废。
- 验证码申请按 IP 限流，内存挑战数量设上限；登录和注册原有限流继续保留。
- 验证码错误、已使用或过期统一返回 422；前端显示“验证码不正确或已过期，请重新输入”，随后自动换一张。
- 验证码接口和图片禁止缓存。验证码用于降低普通注册机和撞库流量，不宣称能阻挡专业 OCR 或分布式攻击。
- 开发与自动化测试可显式关闭验证码；生产配置若关闭应拒绝启动。

## 管理员运营后台

- 运营后台继续只存在于同源 `/admin`，不放回普通用户“我的”或“设置”。
- 只有 `status = 'active'` 且 `role = 'admin'` 的登录账号可读取后台和聚合统计；普通账号保持 404。
- 打开方式：管理员先在姿序首页登录，再把地址栏路径改为 `/admin`；GoAccess 流量报告仍从后台内的受保护入口打开。

## 验收

- 6 位注册密码和修改密码成功，5 位失败；旧密码与旧会话在修改后失效。
- 开启验证码时，无验证码、错误验证码、重复使用验证码均失败；新验证码可完成登录或注册。
- 两个账号保存不同占位 Key 后，数据库中不存在明文，接口和备份均不泄漏，读取时只能得到各自 Key。
- 生产配置允许加密保存个人 Key，但拒绝关闭验证码。
- 普通用户仍无运营数据入口且无法读取管理员 API；管理员 `/admin` 流程保持不变。

## 发布顺序

- 验证码是服务端强制项，旧版 APK 不会发送验证码；不能只更新服务器后继续把旧 APK 当作当前下载版本。
- 正式上线应同批完成新 Web、新服务器和新版 APK：先上传并校验新版 APK，再原子切换服务器与 Web，最后更新版本清单；旧版代码与 APK 保留回滚。
