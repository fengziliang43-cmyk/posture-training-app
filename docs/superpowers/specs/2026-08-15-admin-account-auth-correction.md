# 独立管理员后台与账号能力纠正规范

## 目标

按良 2026-08-15 的反馈纠正 1.0.2 信息架构：运营数据不属于普通用户的“我的”或“设置”，只在独立管理员后台出现；账号与隐私补充修改密码；登录注册同时接受原账号名和标准邮箱地址；体态照片文案与线上真实存储保持一致。

## 独立管理员后台

- 普通“我的”和“设置”不展示“运营数据”入口，也不在后台请求管理员统计。
- 聚合仪表盘迁到独立同源路径 `/admin`，页面不使用普通用户底部导航。
- 只有 `status = 'active'` 且 `role = 'admin'` 的账号可读取 `/admin`、`/api/admin/stats` 和 `/ops/traffic/`。
- 生产 Nginx 在返回 `/admin` 的 HTML 前使用现有 `/api/admin/access` 做服务端鉴权；未登录跳回首页，普通用户返回 404。
- 客户端仍核对当前用户角色。客户端隐藏不是安全边界，API 与 Nginx 才是最终权限边界。
- 不硬编码管理员用户名；当前唯一管理员账号自然成为唯一可见者，未来若显式新增管理员则按同一角色规则授权。

## 账号名与邮箱登录

- 保留现有 3—32 位英文、数字、下划线、点和连字符账号名。
- 同一输入框也接受最长 254 位的标准邮箱地址，例如 QQ 邮箱、Gmail、Outlook 等。
- 邮箱只作为“账号标识 + 密码”使用，复用现有 `username` / `username_normalized` 字段，不新增数据库 schema。
- 邮箱统一按去空格、小写后的值判重和登录；原有账号名继续兼容。
- 本次不发送验证邮件、不提供找回密码，也不接入 QQ/Google OAuth 或第三方授权登录。
- 重复账号名或邮箱统一返回 409；前端明确显示“账号重复了，请直接登录或换一个账号/邮箱”。

## 修改密码

- “我的 → 设置 → 账号与隐私”新增独立修改密码卡片。
- 用户必须输入当前密码、新密码和二次确认；新密码至少 10 位，且不得与当前密码相同。
- 服务端验证当前会话和当前密码后重新计算 bcrypt 哈希，不保存或记录明文密码。
- 修改成功后撤销该账号全部现有会话并清除当前 Cookie，要求使用新密码重新登录。
- 当前密码错误、两次新密码不一致、尝试过于频繁和网络故障均使用安全中文提示，不暴露内部异常。

## 照片文案

- 体态页固定显示：`不做 AI 或医疗诊断；照片只保存在服务器，不发送给 DeepSeek。`
- “服务器”指当前姿序服务器中按账号隔离、经鉴权访问的上传目录；不暗示照片公开可访问。
- 规则页继续说明照片不进入 DeepSeek 请求。

## 验收

- 普通“我的/设置”源码和页面均不存在运营数据入口，也不会请求 `/api/admin/stats`。
- 管理员访问 `/admin` 可看聚合数据；普通用户请求统计 API 为 404，管理员访问探针为 204。
- 账号名、`name@qq.com`、`name@gmail.com` 均可注册并登录；大小写邮箱被视为同一账号。
- 重复账号前端显示明确中文；无后端类名、状态码或请求地址。
- 密码修改后旧密码失效、所有旧会话失效、新密码可登录。
- 体态页显示服务器保存文案；测试、类型检查和生产构建通过。
