# 自适应训练引擎 V3 设计规格

**状态：** 2026-07-15 已批准，包括新增本地数据库表和兼容性迁移。

**目标：** 用可解释、可测试、保守优先的动作级规则引擎，替换“固定模板轮换 + 按顺序截断”的旧计划生成方式。系统根据今日状态、可用时间、近期训练、动作反馈和周训练平衡动态选择动作，并形成稳定的渐进、退阶与减载闭环。

**训练优先级：** 安全 > 体态与动作控制 > 减脂 > 增肌 > 体能。

**医疗边界：** App 不是诊断或治疗工具。不得根据旧影像自行推导左右不对称的侧弯矫正处方；没有专业评估时，单侧动作两边同量。红旗症状必须阻断训练，DeepSeek 不参与选动作或调训练量。

---

## 1. 当前问题

旧引擎存在以下结构性问题：

- 只在四个固定模板之间轮换，不能根据近期训练缺口自由组合。
- 短版和压缩版通过截掉列表尾部生成，可能删掉关键动作而保留低优先级动作。
- 动作库缺少风险、器械、难度、目标和预计耗时元数据。
- 已有进阶函数没有接入每日计划。
- 前端动作勾选不落库，后端不知道具体哪个动作完成、部分完成、跳过或引起不适。
- 替代动作使用静态链条，不能保证替代项是当天最安全、最合适的候选。
- 计划没有算法版本、预计时长和动作选择依据，无法审计和稳定升级。

## 2. 新决策流程

计划生成按以下固定顺序执行：

```text
红旗安全阻断
  -> readiness 与训练量预算
  -> 根据周训练缺口生成动作槽位
  -> 按疼痛、器械和近期不适做硬过滤
  -> 对安全候选做确定性评分
  -> 在可用时间内组合并压缩训练量
  -> 应用维持、进阶、退阶或减载
  -> 保存算法版本、预计时间和选择原因
```

同一输入必须生成同一结果，不使用随机数，不让 AI 改写计划。

## 3. 安全闸门与 readiness

### 3.1 硬阻断

以下任一红旗存在时：

- 腿麻。
- 放射痛。
- 明显无力。
- 大小便异常。
- 突发锐痛。

系统生成“停止训练”计划，动作列表必须为空，仅展示停止训练和就医评估提示。

### 3.2 计划等级

- `recovery`：腰酸较高、睡眠和精神同时很差、最近训练后疼痛明显升高，或本周主训练已足够。
- `reduced`：中等腰酸、肩颈不适、睡眠不足、精神一般，或近期完成率偏低。
- `full`：没有触发以上条件且状态稳定。

readiness 同时输出：

- 0-100 的保守评分。
- 训练量倍率。
- 触发原因列表。
- 时间版本：压缩、短版、完整版。

疼痛和红旗属于硬约束，不能被精神好、睡眠好或 AI 输出抵消。

## 4. 动作元数据

每个动作必须补齐：

- 训练角色：呼吸重置、活动度、上肢拉、肩胛控制、核心抗伸展、核心抗旋转/侧向稳定、臀部稳定、下肢单侧稳定、低冲击有氧、收操。
- 所需器械。
- 难度等级。
- 腰背、肩颈、膝关节、平衡和冲击负担等级。
- 对体态、力量、减脂和体能目标的贡献分。
- 可用于完整、降级或恢复计划的范围。
- 退阶/替代动作。
- 次数或时长的进阶步长与安全上限。

动作库仍保持白名单制，不允许 DeepSeek 或用户自由文本注入新动作。

## 5. 动作槽位与周平衡

完整训练从以下槽位动态组合：

- 呼吸或活动度准备。
- 上肢拉力。
- 肩胛控制。
- 核心抗伸展。
- 核心抗旋转或侧向稳定。
- 臀部/骨盆稳定。
- 可控单侧下肢。
- 低冲击有氧或收操。

短版和压缩版不能简单截断动作列表，而应保留当天优先级最高的槽位。系统根据最近 7-14 天各训练角色的暴露次数，优先补足缺口，同时避免连续两次重复同一动作。

## 6. 候选过滤与评分

### 6.1 硬过滤

候选动作在以下情况直接排除：

- 所需器械不可用。
- 不支持当前计划类型。
- 负担等级超过今日疼痛条件允许范围。
- 最近因疼痛或动作控制问题停止该动作，仍处于保守冷却期。
- 已在当天计划中出现。

### 6.2 确定性评分

安全候选按以下因素评分：

- 是否匹配当前槽位。
- 是否补足本周训练角色缺口。
- 是否符合安全、体态、减脂、增肌、体能的目标顺序。
- 最近是否连续重复。
- 最近是否稳定完成。
- 是否常被替换、跳过或因不适停止。
- 难度是否匹配今日 readiness。
- 预计耗时是否适合剩余时间。

分数相同时使用动作库固定顺序作为稳定决胜，不使用随机选择。

## 7. 时间与训练量预算

系统按组数、次数/时长、休息和动作切换估算总时间。

- 生成结果不得明显超过用户填写的可训练时间。
- 时间不足时先减少低优先级槽位，再缩减组数或次数；不能盲目删除列表尾部。
- 恢复日的步行时长可在安全范围内适配剩余时间。
- 降级日通过减少总量、降低难度和选择低负担动作实现，不只是改标题。

## 8. 渐进、退阶和减载

- 连续两个稳定周完成某动作，训练后腰酸没有明显升高，才允许小幅进阶。
- 每次只改变一个变量：增加少量次数、增加 5 秒，或在确有需要时增加 1 组。
- 引体向上优先增加可控总次数，不自动加负重。
- 出现动作级疼痛反馈、训练后腰酸上升 2 分及以上、完成率明显下降时，不进阶，并降低训练量或暂时换成低负担候选。
- 每个五周周期的第 5 周自动减载约 20%-30%。
- 旧数据不足时从默认保守量开始，不假装已经了解用户能力。

## 9. 动作级反馈闭环

每个动作需要保存：

- `completed`、`partial` 或 `skipped`。
- 反馈原因：无、时间不足、疲劳、不适、动作控制困难。
- 动作在计划中的顺序和动作 id。

训练结束仍保存整体完成状态和训练后腰酸。整体状态由动作结果自动归纳：全部完成为 `completed`，部分执行为 `partial`，全部跳过为 `skipped`。

旧版 APK 没有动作结果时，接口仍可保存整体训练记录，保证向后兼容。

## 10. 本地数据库迁移

允许以下兼容性变更：

1. `plans` 新增算法版本、预计时长和决策摘要字段；旧计划标记为 `legacy-v1`。
2. 新增 `workout_exercise_logs`，记录动作级完成和反馈。
3. 备份导出同步包含新字段和新表。

迁移必须幂等，不删除、不覆盖旧记录；旧数据库启动后自动补齐结构。

## 11. UI 与解释

今日任务需要显示：

- 预计总时长。
- 今日计划等级和 readiness。
- 每个动作的选择原因。
- 动作完成、部分完成、跳过和反馈原因。
- 训练后腰酸。

DeepSeek 只能把本地决策摘要改写成自然语言。它不能新增动作、改变顺序、修改组数/次数/休息、覆盖安全阻断或读取体态照片。

## 12. 验收标准

- 红旗输入始终返回空动作列表。
- 高腰酸不会选择高腰背负担动作。
- 明显肩颈不适不会选择高肩颈负担动作。
- 同一计划不重复同一动作。
- 同一输入与历史产生确定性相同结果。
- 完整、短版和压缩版都保留必要训练槽位，预计时长不超预算容差。
- 两个稳定周后最多进阶一个变量；疼痛升高时不进阶。
- 第 5 周正确减载。
- 动作级结果可保存、覆盖重提、离线排队并进入下一次选择。
- 旧计划、旧训练记录和旧版完成接口仍可读取和使用。
- 备份包含新结构但不包含 DeepSeek API Key。
- 全量测试、类型检查、构建和 Android APK 打包通过。
