# 更新检查、认证错误与管理员数据设计规范

## 目标

在不暴露服务端内部错误、不绕过移动系统安全机制、也不新增敏感用户数据采集的前提下，完成三个入口：友好的登录/注册失败提示、设置中的版本检查、仅管理员可见的运营数据页。

侧弯风险自查的三张新图先作为独立候选，不进入本次代码替换；只有良确认图像后才替换现有插图。

## 登录与注册错误

- 登录 401 统一显示：`账号或密码不正确，请重新检查后再试。`
- 登录 429 显示尝试频繁提示；网络或服务端故障显示稍后重试提示。
- 注册 409 显示账号名已被使用；400、429、网络故障分别显示可执行的中文提示。
- 认证页面不得展示异常类名、HTTP 状态、后端原始消息或请求地址。
- 服务端仍保留通用错误信息供工程诊断，但认证 UI 必须使用独立的安全映射。

## 检查更新

### 入口与页面

- 在“我的 → 设置”增加“检查更新”入口。
- 详情页显示当前平台、当前版本、检查状态、最新版本、发布日期和更新说明。
- 用户主动点击“检查更新”；请求失败时显示可重试的中文提示，不把 URL 或堆栈暴露给用户。

### 版本来源

- 官网提供只读版本清单 `/api/releases/latest`，请求使用 `no-store`，并复用现有原生客户端 CORS 边界。
- Android、iOS 与 Web 分别配置版本、构建号、发布日期、更新说明和安装地址。
- 客户端只接受 HTTPS 官网地址；版本比较按数字分段，不使用字符串字典序。
- 应用版本号、Android `versionName/versionCode`、iOS `MARKETING_VERSION/CURRENT_PROJECT_VERSION` 和官网清单必须由测试防止漂移。

### 平台行为

- Android：用户选择后打开官网 APK 下载地址；下载完成后由 Android 系统继续安装，并由用户完成“未知来源”和安装确认。不得宣称或实现绕过系统确认的静默安装。
- iOS：只打开 App Store 或 TestFlight 安装地址，不直接下载或侧载 IPA。
- Web/PWA：提示网站会自动更新，并可触发 Service Worker 检查后刷新。
- 安装地址尚未发布时，页面明确显示“新版正在准备”，不提供失效按钮。

## 管理员运营数据

### 权限

- 复用现有 `users.role = 'admin'`，不新增数据库结构。
- `/api/admin/stats` 必须先验证会话，再核对账号为 active admin。
- 非管理员返回 404，前端不显示“运营数据”入口。

### 数据范围

管理员页只显示聚合值：

- 有效账号总数、新增账号（7 天 / 30 天）、已完成训练档案数；
- 活跃用户（7 天 / 30 天，按会话 `last_seen_at` 去重）；
- 近 7 天状态记录、近 7 天完成训练、累计完成训练；
- 数据生成时间。

不得显示用户名列表、体态照片、疼痛值、体重、训练明细、IP 或设备标识。

### 网站访问量

- 应用数据库当前没有页面访问表，不能把 API 请求数伪装为网站点击量。
- 网站流量采用现成的 GoAccess 读取 Nginx access log，输出私有网页仪表盘；它属于服务器软件安装和 Nginx 权限配置，必须获得单独授权后部署。
- GoAccess 未接入前，管理员页明确标记“网站访问统计未接入”，不显示假 0。

## 验收

- 错误账号登录时，页面只出现友好中文提示，不包含 `ApiRequestError`、`401`、`invalid credentials` 或 `/api/auth/login`。
- 设置页存在“检查更新”，当前版本时显示“已是最新版”；新版存在时按平台提供正确动作。
- 非管理员请求统计接口得到 404，管理员可看到聚合数据。
- 管理员接口和页面均不泄露个人明细。
- 测试、TypeScript 检查和生产构建通过。
