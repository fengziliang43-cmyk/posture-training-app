# 个人 DeepSeek、验证码与密码规则实施计划

1. 新增服务端密钥封装器，使用 AES-256-GCM 和版本化密文；仓库层按用户加解密 DeepSeek Key，并兼容首次读取时把旧明文转换为密文。
2. 调整生产配置校验：允许开启个人 DeepSeek Key，保留紧急关闭开关；公开环境强制验证码开启。
3. 新增有容量上限、5 分钟有效、一次性消费的验证码服务和 `/api/auth/captcha`；登录、注册校验验证码后再进入原认证流程。
4. 扩展公开认证 capability、Web API 和登录/注册界面，加入验证码图片、输入框、刷新和安全中文错误提示。
5. 把注册、修改密码的前后端最低长度改为 6 位，同时提示用户优先使用 10 位以上独立密码。
6. 补充验证码、密钥密文/隔离/备份、生产配置和 Web 错误映射测试；回归管理员 `/admin` 隔离。
7. 运行 `npm test`、`npm run lint`、`npm run build`、`git diff --check`、敏感文件与生成物扫描。
8. 本地验证完成后单独等待 commit/push、生产 `.env` 调整、部署与新版 APK 的明确授权；上线时先交付新版 APK，再同步启用服务端验证码，避免旧 APK 无法重新登录却仍被标记为最新版。
